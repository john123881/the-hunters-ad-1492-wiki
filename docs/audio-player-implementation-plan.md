## 1. 目標

建立全站共用播放器，讓使用者輸入規則書上的語音代碼直接播放。切換頁面後保留音訊與進度，桌面及手機皆可操作。

目前沒有劇情卡、任務卡、地圖卡與語音代碼之間的可靠對照資料，因此播放器不從卡片自動推導代碼，也不在卡片或已放置卡片加入語音播放按鈕。所有新播放都由玩家手動輸入規則書上的代碼；共用歷史中的既有代碼則可直接重播。

第一階段處理播放器、代碼解析、音訊索引與少量音檔驗證，不將約 1.07 GiB 音訊直接放進前端建置產物。

## 3. 架構

在 React 頂層加入 AudioPlayerProvider，全站只建立一個 HTMLAudioElement。預計建立：

- src/audio/AudioPlayerProvider.tsx
- src/audio/GlobalAudioPlayer.tsx
- src/audio/AudioCodeInput.tsx
- src/audio/useAudioPlayer.ts
- src/audio/audioCode.ts
- src/audio/audioManifest.ts

Provider 管理目前音訊、播放狀態、進度、音量、載入錯誤及介面展開狀態；戰役共用播放紀錄由 Hono API 與 D1 管理。

正式環境建議用 Cloudflare R2 儲存音訊，前端與 Worker 只保留輕量 manifest。音訊不進入 public 或 Worker bundle，實際路徑由 manifest 提供，播放器不自行拼接網址。

## 4. Manifest

新增生成腳本讀取 data/audio_map.json，輸出穩定排序的 manifest。每筆包含 code、category、title、path，可選擇加入 duration。

生成時驗證代碼唯一、檔案存在與分類映射，另輸出遺失、重複及未映射項目報告。

## 5. 輸入規則

| 使用情境 | 格式 | 範例 |
| --- | --- | --- |
| 基礎任務前言 | Q 加任務編號 | Q1 |
| 基礎任務勝利 | V 加任務編號 | V1 |
| 基礎任務失敗 | L 加任務編號 | L1 |
| 瓦瑟堡任務前言 | W 加任務編號 | W2 |
| 瓦瑟堡任務勝利 | VW 加任務編號 | VW1 |
| 瓦瑟堡任務失敗 | LW 加任務編號 | LW2 |
| 劇情 | 移除章節句點 | 37.22 或 3722 |
| 角色 | F 加三位編號 | F001 |

正規化會去除空白、句點與常見連字號，英文字母轉大寫。VW 與 LW 優先判斷，37.22 轉成 3722。找不到 manifest 項目時顯示錯誤，不送出無效請求，也不自動播放模糊比對結果。

## 6. 使用者介面

### 全站入口

在導覽列或固定工具列加入「語音」按鈕。展開後提供代碼輸入、格式提示與播放按鈕；按 Enter 也能播放。

### 桌面版

使用底部固定播放器。收合時顯示音訊名稱、播放或暫停、時間、進度、音量及展開按鈕；展開後增加代碼輸入與最近紀錄。主內容保留底部安全間距。

### 手機版

預設顯示底部迷你播放器；展開後使用底部抽屜，依序顯示目前音訊、播放控制、進度、代碼輸入及最近紀錄。需處理 iPhone safe area，鍵盤開啟時輸入與播放按鈕仍可見。

## 7. 狀態與行為

播放器狀態包含 idle、resolving、loading、ready、playing、paused、ended、error。

- 載入中顯示 spinner 與「載入語音中」。
- 可播放後才啟用播放按鈕。
- 網路失敗提供重試。
- 找不到代碼時保留輸入內容。
- 新代碼播放時停止上一段並歸零。
- 相同代碼若暫停則繼續，若結束則重播。
- 頁面切換不中斷。
- 連續快速輸入只接受最後一次請求結果。

## 8. 戰役共用播放紀錄

播放紀錄以戰役為單位寫入 D1，讓同一戰役的所有玩家在手機與電腦上看到一致紀錄。每筆包含 campaignId、code、category、title、playerNumber、playerAlias 與 playedAt。

- 音訊真正進入 playing 狀態後才記錄，載入失敗不留下錯誤紀錄。
- 紀錄採追加式寫入，同一代碼重播會保留每次時間與操作者，呈現完整時間軸。
- 前端預設顯示最近 50 筆，並可重新播放任一筆。
- API 只允許目前戰役成員讀寫自己的戰役紀錄，禁止跨戰役存取。
- 追加紀錄不參與戰役版本鎖，不會因多人同時播放產生 409 衝突。
- 未登入時仍可使用播放器，但不寫入或顯示戰役共用紀錄，介面提示登入後才能同步。
- 第一版不提供一般玩家永久刪除共用紀錄，避免其中一名玩家誤刪全隊歷史；如需清理功能，另設管理權限與確認流程。
- 播放進度屬於個人即時狀態，不寫入共用紀錄。

## 9. 手動輸入界線

- 新播放一律由全站播放器的輸入框接收語音代碼。
- 不假設劇情卡、任務卡、地圖卡、已放置卡片或角色編號等同於語音代碼。
- 不在上述卡片、搜尋結果或進度抽屜加入語音播放按鈕。
- 共用播放紀錄可直接重播已成功播放過的代碼，因為該代碼已由玩家手動確認。
- 未來只有在取得並驗證正式對照資料後，才另行規劃對應功能；對照資料需獨立維護，不能靠前端規則猜測。

## 10. 效能與快取

- 首次載入只下載 manifest，不下載 MP3。
- 選定代碼後才載入音訊，不預載全部 722 個檔案。
- Manifest 使用版本檔名與長效快取。
- MP3 設定 Content-Type、ETag 與 Cache-Control。
- 播放進度更新節流，避免全站高頻 re-render。
- 拆分控制函式與高頻進度訂閱，避免不相關頁面重繪。
- 第一版不做預測式下一章預載。

## 11. 無障礙

所有控制可使用鍵盤；輸入欄有明確 label；播放狀態使用 aria-live；錯誤不只依賴顏色；支援 prefers-reduced-motion。

## 12. 分階段實作

### 階段一：資料基準與 manifest

解析 audio_map、建立代碼映射、產生 manifest 與驗證報告，選少量音訊作為本機測試集。

交付：輸入代碼可準確解析成唯一音訊項目。

### 階段二：播放器核心

建立 Provider 與 Hook，完成播放、暫停、重播、進度、音量、錯誤及重試，並保證頁面切換不中斷。

交付：任何頁面都能呼叫 playByCode。

### 階段三：響應式介面

加入全站入口、桌面底部播放器、手機迷你播放器與底部抽屜，處理鍵盤及 safe area。

交付：桌面與手機都能輸入規則書代碼播放。

### 階段四：戰役共用播放紀錄

- 新增 campaign_audio_playback_logs D1 migration 與 Drizzle schema。
- 新增查詢及追加播放紀錄的 Hono API，驗證戰役登入與資料隔離。
- 播放器顯示最近 50 筆共用紀錄、操作者與播放時間。

交付：同一戰役玩家能看到一致的播放時間軸，並能從歷史紀錄重播已確認的語音代碼；新的語音仍由玩家手動輸入。

### 階段五：R2 正式媒體流程

建立 R2 bucket 與媒體網域，上傳音訊，設定快取標頭，重新產生正式 manifest 並驗證正式站播放。此階段涉及外部資源，執行前另行確認。

### 階段六：容量優化

去除重複檔，統一取樣率與位元率策略，經語音品質 A/B 測試後決定是否批次轉碼，並保留原始音檔。

## 13. 測試

### 單元測試

- 合法代碼正規化。
- 37.22 轉成 3722。
- VW、LW 不被誤判為單字母前綴。
- 空輸入、不合法字元與未知代碼。
- Manifest 重複代碼。
- 共用播放紀錄的戰役隔離、排序與頁數上限。
- 多人同時追加紀錄不互相覆蓋。
- 音訊失敗時不寫入播放紀錄。

### 元件與瀏覽器驗收

- 載入、播放、暫停、結束、錯誤與重試。
- Enter 送出與快速切換只保留最新請求。
- 收合及頁面切換後繼續播放。
- 桌面 Chrome、Edge、iPhone Safari 與 Android Chrome。
- 鍵盤開啟時輸入和播放按鈕可見。
- 慢速網路下顯示載入狀態。
- Hono 頁面與 R2 音訊完整串接。
- Manifest 有資料但物件缺失時顯示正確錯誤。

## 14. 驗收標準

- Q1、V1、L1、W2、VW1、LW2、F001 與 37.22 可播放正確音訊。
- 不合法或不存在的代碼不播放其他音訊。
- 全站同時只有一個音訊播放實例。
- 切換頁面後播放不中斷。
- 手機播放器不水平溢出，也不遮住主要操作。
- 首次開站不下載 MP3。
- 播放失敗可重試，錯誤訊息清楚。
- 手動輸入與歷史紀錄重播共用 manifest 和播放器。
- 型別檢查、建置、單元測試及瀏覽器驗收通過。

## 15. 實作前待確認

以下不阻擋階段一，可在正式 R2 上傳前確認：

- 正式媒體網域名稱。
- 音訊檔名全面改成可讀代碼，或由 manifest 映射現有檔名。
- 是否需要倍速播放。
- 是否需要背景播放與鎖定畫面控制。
